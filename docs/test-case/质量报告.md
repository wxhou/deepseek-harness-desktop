## 五、关键覆盖率说明

- **有效等价类**：每个 POINT 至少 1 条正向用例（P1/P2），核心流程全覆盖。
- **无效等价类**：关键异常均覆盖——空值/非法名称（档案）、缺失 tag/未下载版本（核心）、网络不可达/摘要缺失（安装）、目录不存在/使用中拒绝（档案/核心卸载）、端口被占（服务启动）等，异常用例以 `CORE_*`/`PROFILE_*`/`DOWNLOAD_*` 等错误码作为可判定断言。
- **边界值**：覆盖范围型输入——档案名称 64 字符上限、语言（zh-CN/en）切换、主题（light/dark/system）、端口（3080/3081）、版本号边界、Node 版本门槛、下载进度 0–50/50–100 两阶段、目录/文件路径隔离等。
- **反向用例**：共 32 条，主攻安装中断、核心切换失败回滚、版本不可卸载、档案不可删除、网络异常、插件损坏恢复等失败路径。

## 六、校验结论

1. **格式校验**：35 个 POINT 文件全部通过 `validate.py`（0 错误 / 0 警告），字段（优先级、测试类型、前置条件、测试步骤、预期结果）符合文本协议 v0.2，步骤与预期结果编号从 1 连续且数量一致。
2. **重复检测**：对全部 35 个 POINT 文件执行 `--duplicates-only`，0 对疑似重复。
3. **说明**：`all_cases.md` 为按 ITEM/POINT 分组的合并汇总文件（`# ITEM`、`## POINT` 标题），供人工评审；其结构标题会被 `validate.py` 误判为用例标题，因此格式校验的对象是各 POINT 源文件。

## 七、下一步建议

- 人工评审关键 KPI（核心切换回滚、档案隔离、插件恢复、安装中断自愈）。
- 按需导出 Excel：`uv run <skill>/scripts/to_excel.py docs/test-case/ -o docs/test-case/export.xlsx`。
- 依据真实运行结果校准预期结果中的版本号与错误码。
