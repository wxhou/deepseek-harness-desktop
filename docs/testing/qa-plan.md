# 质量保证计划：deepseek-harness-desktop

> 本计划定义本项目的质量验证范围、ISO 25010 质量特性验证、质量门禁、
> GitHub Issue 质量标准、标签与优先级规范、依赖管理及估算评审。
> 与 `test-strategy.md`、`test-issues-checklist.md` 配套使用。

---

## 1. 质量验证范围

本项目为「零环境」桌面应用（Tauri 2 + React 18），质量保证覆盖：

- **后端**：下载/装配、核心多版本管理、档案管理、插件管理、CLI shim + PATH、自更新、进程生命周期、健康检查、命令桥。
- **前端**：安装状态机、下载进度、内嵌 iframe、侧边栏、配置对话框、主题、i18n、store 状态管理。
- **跨层**：`invoke` 命令契约、WebView 嵌入、消息桥、进程启动/停止、PATH 注册后的 CLI 可用性。
- **发布**：release（`:3080` / `~/.dsh`）与 debug（`:3081` / `~/.dsh.dev`）隔离，三平台安装包。

---

## 2. ISO 25010 质量特性验证

| 特性 | 验证内容 | 验证方法 |
| --- | --- | --- |
| **功能适合性** | 完整性、正确性、适当性 | 功能测试 + E2E，覆盖 100% 验收标准 |
| **性能效率** | 时间行为、资源利用、容量 | 首启装配计时、内存/CPU 占用、核心切换耗时 |
| **可用性** | 界面美观、可访问性、可学习性、可操作性 | 可用性测试 + WCAG 检查（对比度/键盘/焦点/暗色） |
| **安全性** | 机密性、完整性、认证授权 | 权限/跨源校验、插件来源白名单、本地执行警示 |
| **可靠性** | 容错、恢复、可用性 | 断网/端口占用/进程被 kill 场景 + 健康检查恢复 |
| **兼容性** | 浏览器/设备/集成兼容 | 三平台矩阵；debug+release 同机共存 |
| **可维护性** | 代码质量、模块化、可测试性 | lint/类型检查/覆盖率/组件拆分/中文注释 |
| **可移植性** | 环境适配、安装流程、替换性 | win32 极简模式、安装包、自更新替换 |

## 3. 质量门禁与检查点（Quality Gates）

### 3.1 入口标准（Entry Criteria）

- [ ] 被测功能实现已完成并通过代码评审。
- [ ] 相关单元测试通过且无未处理 panic。
- [ ] `pnpm typecheck`、`pnpm lint`、`cargo check` 通过。
- [ ] 测试环境（三平台、模拟异常条件）就绪。

### 3.2 退出标准（Exit Criteria）

- [ ] 所有测试类型完成且通过率 ≥ 95%。
- [ ] 无 critical / high 级缺陷遗留。
- [ ] 性能基准达标（装配/切换时间、内存占用）。
- [ ] 安全验证通过（无 critical 漏洞、来源白名单生效）。
- [ ] 质量门禁全部健康。

### 3.3 质量度量指标

- [ ] 测试覆盖率：关键路径行 > 80%、分支 > 90%。
- [ ] 缺陷密度：< 阈值（按正常范围）。
- [ ] 性能：装配/切换响应时间在可接受阈值内。
- [ ] 可访问性：WCAG AA 合规。
- [ ] 安全性：零 critical 漏洞。

### 3.4 升级流程（Escalation）

- 质量失败 → 记录缺陷（含严重度/复现步骤）→ 按严重度升级 → 阻塞发布直至回归通过。

## 4. GitHub Issue 质量标准

- [ ] **模板合规**：所有测试 Issue 遵循 `test-issues-checklist.md` 中的模板结构。
- [ ] **必填字段**：标题、描述、范围、验收标准、标签、估算、依赖均完整且准确。
- [ ] **标签一致**：全项目统一使用第 5 节约定标签。
- [ ] **优先级分配**：按风险矩阵（`test-strategy.md` 1.3）确定优先级。
- [ ] **价值评估**：标注业务价值与质量影响。

## 5. 标签与优先级规范

### 5.1 测试类型标签

| 标签 | 用途 |
| --- | --- |
| `unit-test` | 组件级单元测试 |
| `integration-test` | 接口/组件间集成测试 |

### 5.2 质量标签

| 标签 | 用途 |
| --- | --- |
| `quality-gate` | 质量门禁 |
| `iso25010` | ISO 25010 特性验证 |

- `test-critical`（关键）/ `test-high`（高）/ `test-medium`（中）/ `test-low`（低）。

### 5.4 组件标签

- `frontend-test` / `backend-test` / `api-test` / `database-test`。

## 6. 依赖验证与管理

- [ ] **循环依赖检测**：阻止环路阻塞关系（如 E2E → 集成 → 单元）。
- [ ] **关键路径分析**：识别影响交付节点的测试依赖（装配 → 内核切换 → 档案切换 → 插件 → CLI → 自更新）。
- [ ] **风险评估**：延迟影响分析；如上游 `deepseek-harness-pkg` 或 GitHub 网络不可达。
- [ ] **缓解策略**：保留本地产物、断网降级、插件恢复机制、自更新失败回退。

---

## 7. 估算准确性与评审

- [ ] **历史数据分析**：参考过往版本装配/切换/插件耗时。
- [ ] **技术负责人评审**：由 Rust / React / E2E 资深成员复核复杂度估算。
- [ ] **风险缓冲**：对高不确定性任务（如首启装配、Windows 极简修复、自更新）预留缓冲。
- [ ] **估算精化**：每轮迭代回顾实际 vs 估算并精化。

---

## 8. 测试完成与发布清单

- [ ] 全部测试类型执行完成，通过率达标。
- [ ] 覆盖率与质量度量达标。
- [ ] 关键路径 E2E 冒烟通过（装配/切换/插件/CLI/更新）。
- [ ] 三平台安装包验证通过（Windows / macOS / Linux）。
- [ ] 双语文案与中文注释一致性检查通过。
- [ ] 安全与合规检查无遗留高风险项。
